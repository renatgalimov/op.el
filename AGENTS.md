- Always rebase your branch against the "main" branch in the `renatgalimov/op.el` GitHub repo. If you fail to rebase, *stop the operation*;
- Use `git log` to expand your context and see the reasons behind certain actions.
- The environment **should have** `op` tool installed. If it's not available - *stop the operation*;
- The environment **should have** `gh` installed.  If it's not available - *stop the operation*;
- GitHub access must use either authenticated `gh` (`gh auth status` must succeed) or the `vpetersson/agent-iap` MCP gateway's GitHub upstream. If neither is available, report an error and stop. Do not expose credentials or bypass gateway policy.
- When using `gh`, only `gh api` and `gh auth status` commands may be used; avoid other subcommands. When using agent-iap, use its GitHub API upstream for equivalent requests.
- To read a GitHub issue, use `gh api repos/renatgalimov/op.el/issues/<issue id>` or the equivalent agent-iap GitHub API request.
- When tests need recorded data, do not fabricate fixtures. Ask the human to create the entry in 1Password, then record traffic from the real `op` CLI through mitmproxy. Review recordings for sensitive data before sharing or committing them.
- When recording requires sign-in, start mitmproxy and a GNU screen session configured to use the proxy and trust its CA first. Ask the human to attach to that screen session and sign in to `op`; do not ask them to share credentials or session tokens in chat.
- Do not mock `op` calls using Emacs Lisp (e.g. `cl-letf` on `call-process`). Tests should invoke the real `op` CLI through mitmproxy rather than `bin/op.py`. Replay must fail closed for unrecorded requests and must not report successful mutations unless subsequent reads reflect the changes.
- Prefer `member` (or `member-ignore-case`) over nested `seq-some` for list membership checks. Use `(and (member-ignore-case value list) value)` instead of iterating the list with a lambda that compares each element.
- Apply the stepdown rule: define high-level functions first, followed by their helpers. Each function should be followed by the lower-level functions it calls. Do not mix abstraction levels within the same function.
